## 0. 한눈에 보기 (Summary)

- **무엇을**: 텔레그램 채널 "**사제콩이_서상영**"(`@ehdwl`)에 매일 새벽 게시되는 미국 증시 시황 브리핑을 자동 수집·구조화하여,
  **매일 06:30(KST) 링크 하나로 열어 보는 데일리 리포트 페이지**를 생성한다.
- **핵심 화면**: 시황 요약 + 주요 지수 → **오늘 언급된 종목 리스트** → **종목 서머리 = 캔들차트 + 등락 이유 + 원문 근거**.
- **v2.0에서 달라지는 것 (3축)**
  1. **미래에셋증권 CI 전면 적용** — Mirae Asset Orange / Blue, 승인 폰트, 1px 오렌지 섹션 룰, 시그니처 테이블, 화이트 캔버스.
  2. **실데이터 연결** — 운영에서 샘플·합성 데이터 폴백을 제거하고, 실제 텔레그램 수집 · Claude 구조화 요약 · 실제 시세 기반 캔들차트로 전환.
  3. **정시성과 보존** — 06:30 정시 생성(현행 실측 08:00~08:40) 및 날짜별 아카이브 영구 보존.
- **결정 사항**: 13장 결정 로그. 핵심 결정 4건은 2026-09-09 확정 — **D1 GitHub Pages 공개 링크 · D2 조기 예약 + 대기 루프 · D3 공개 미리보기 우선 + 세션 폴백 · D4 무료 비공식 시세 조합**.
  나머지(D5~D8, D10)는 권고 기본값으로 진행하고, D9(로고 자산)·D11(컴플라이언스 확인)은 사용자 측 조치가 필요하다.

**시나리오**
1. 06:30 고정 링크를 열면 오늘 브리핑이 미래에셋 CI 리포트 형태로 보인다. 지수 보드 → 종목 리스트를 훑고, 종목을 탭하면 캔들차트와 등락 이유·근거가 뜬다.
2. 브리핑이 아직 게시되지 않았다면 "오늘 브리핑 대기 중 (06:30 기준)" 상태와 어제 브리핑 링크가 보이고, 게시되면 10분 이내 갱신된다.

4. 아카이브에서 날짜 또는 종목명으로 지난 브리핑을 찾아 당시 등락 이유를 다시 본다.

## 4. 기능 요구사항 (Functional Requirements)

### 4.1 수집 (Ingestion)
| ID | 요구사항 |
| --- | --- |
| FR-1.1 | 대상 채널의 **당일(KST) 신규 메시지**를 수집한다. 수집 방식 **D3 확정: 공개 미리보기(`https://t.me/s/ehdwl`) 우선, 실패 시 개인 세션(Telethon) 폴백**. 미리보기 파서는 메시지 ID·게시 시각(`datetime` 속성)·본문을 추출하고, 결과가 비어 있거나 파싱에 실패하면 세션 수집으로 전환한다. 두 경로는 동일한 메시지 구조로 정규화한다. |
| FR-1.2 | 분할 게시(①②③) 재조립: **같은 날 00:00~24:00 KST에 게시된 모든 메시지**를 시간순으로 결합하여 하나의 브리핑으로 만든다(당일 채널 전체 내용 포함, 2026-09-09 사용자 지시). 메시지 ID·게시 시각을 함께 보존한다. |
| FR-1.3 | **게시 감지**: 실행 시점에 당일 메시지가 없으면 실패로 끝내지 않고 8장의 재시도 정책에 따라 대기·재시도한다. |
| FR-1.4 | 원문과 메타데이터(메시지 ID, 게시 시각, 채널, 수정 여부, 첨부 유무)를 원본 그대로 `archive/YYYY-MM-DD/raw.txt`, `meta.json`에 보존한다. |
| FR-1.5 | 같은 메시지 ID의 재수집·수정 메시지는 idempotent하게 처리한다(재실행 시 결과 동일). |
| FR-1.6 | **운영 모드 폴백 금지**: 수집 실패·미게시 시 샘플 데이터로 대체하지 않는다. 대신 "오늘 브리핑 대기 중" 상태 페이지(+ 최근 브리핑 링크)를 게시한다. 샘플은 `--fixtures`·로컬 개발·테스트 전용으로만 허용한다. |
| FR-1.7 | 휴장 처리: 09:00 KST까지 미게시면 "오늘은 브리핑이 없습니다(미국 휴장 등)"로 종료하고 아카이브·고정 링크는 최근 브리핑을 유지한다. |

### 4.2 구조화·요약 (Structuring)
| ID | 요구사항 |
| --- | --- |
| FR-2.1 | Claude **도구 호출(구조화 출력)** 로 다음을 추출한다: `market_overview`(2~4문장), `indices[]`(지수명·값·등락률), `stocks[]`(종목명·티커·시장·방향·등락률·등락 이유 1~3줄·**원문 근거 발췌**), `themes[]`(업종·테마, 옵션), `kr_outlook`(한국 증시 관전 포인트). |
| FR-2.2 | 종목 마스터로 티커를 확정한다. 규칙 기반 추출은 본문의 **"종목명(+x.xx%)" 표기를 모두 포착**하므로 마스터에 없는 종목도 등락률·이유와 함께 표시된다(티커 없음 → 차트 없음). 미매핑 종목은 `status.json`에 기록해 마스터 보강(FR-8.4)에 사용한다. |
| FR-2.3 | **근거 필수**: 모든 등락 이유에는 원문 발췌(evidence)가 따라야 한다. 원문에 없는 사실 생성 금지(시스템 프롬프트) + **사후 검증**(evidence가 원문에 실제 존재하는지 문자열 대조). 검증 실패 종목은 규칙 기반 발췌로 대체하고 배지를 표시한다. |

| FR-2.5 | 요약 모델·프롬프트 버전을 `brief.json`에 기록해 품질 회귀를 추적한다. |
| FR-2.6 | 원문 노출 범위: 종목별 근거 발췌 + 원문 메시지 링크(`https://t.me/ehdwl/<message_id>`)만 제공한다. 원문 전문 섹션은 넣지 않는다(2026-09-09 사용자 지시로 추가 후 같은 날 제외). 당일 메시지 전문은 아카이브 `raw.txt`·`brief.json`에만 보존한다. |

### 5.1 원칙

- **모서리 sharp**(카드 4px 이하, 버튼 2px, 테이블 0). 그라데이션·이모지·드롭섀도 금지. 이탤릭 금지.
- **다크모드 미제공**(v0.1의 다크모드는 제거). 화이트 캔버스 단일 테마.
- **로고·워드마크·사인오프 흉내 금지**. 공식 로고 자산이 없으면 로고 영역을 비워 둔다(D9).

## 8. 스케줄 및 신뢰성 설계

### 8.1 하루 타임라인 (KST)
| 시각 | 이벤트 | 시스템 동작 |
| --- | --- | --- |
| 05:00 / 06:00 | 미국 정규장 마감(서머타임 / 표준시) | — |
| ~05:30–07:00 (가설) | 채널에 브리핑 분할 게시 | 게시 감지 대상. 실제 분포는 O1에서 계측 |
| **06:30** | **목표 생성 시각** | 게시 완료면 즉시 생성·배포(약 1~2분). 미게시면 "대기 중" 상태 게시 |
| 06:30 ~ 09:00 | 게시 감지 계속(8.4) | 5분 간격 폴링. 게시 감지 시 10분 이내 생성. 마지막 메시지 후 5분 지연(분할 게시 완료 대기) |
| 09:00 | 마감 | 미게시면 "오늘 브리핑 없음"으로 종료 + 운영자 알림 |

### 8.2 정시성 확보 방안 비교 (D2)
| 방안 | 동작 | 정시성 | 비용/운영 | 비고 |
| --- | --- | --- | --- | --- |
| **A. 조기 예약 + 대기 루프 (확정)** | 20:00·20:30·21:00 UTC(05:00~06:00 KST) 예약을 복수로 걸고, 먼저 시작한 잡이 게시를 감지하면 생성, 미게시면 06:30까지 대기 후 상태 게시. 이후 15분 간격 재시도 예약 | 중~상 (지연이 1.5~2h이면 05:00 예약이 06:30~07:00에 시작) | 무료, 추가 인프라 없음 | 완전한 정시 보장은 아님. `concurrency`로 중복 실행 방지 필수 |
| B. 외부 크론 → `workflow_dispatch` | cron-job.org 등 외부 서비스가 06:30 정각 GitHub API 호출 | 상 (분 단위) | 외부 서비스 계정 + fine-grained PAT 관리 | PAT 만료·외부 의존 |
| C. 자체 서버 cron | 사내/개인 서버 또는 무료 VM에서 06:30 실행 후 Pages(또는 사내 웹서버)로 푸시 | 최상 | 서버 운영·보안 관리 | 사내 배포(D1-C)와 결합 시 자연스러움 |
| D. 현행 유지 | 21:30 UTC 단일 예약 | 하 (실측 08:00~08:40) | 없음 | 요구사항 미충족 |

### 8.3 재시도·중복 방지·시간대
- 실행 단위는 idempotent: 같은 날짜·같은 메시지 집합이면 결과가 동일하고, 아카이브 커밋은 변경 없으면 생략.
- `concurrency: group=brief-<date>`로 동시 실행 방지, 대기 중 실행은 취소하지 않는다.
- 모든 스케줄은 UTC로 기술(KST는 서머타임 없음 → 고정 -9h). 미국 서머타임 전환(3월·11월)으로 게시 시각이 1시간 이동할 수 있으므로 재시도 창을 09:00까지 넉넉히 둔다.
- 주말·미국 휴장일에는 브리핑이 없을 수 있다. 미게시 종료 시 "휴장" 사유를 status에 남기되 실패로 취급하지 않는다.

### 8.4 확정 방안 A 상세 설계 (D2)
- **예약**: `.github/workflows/daily-brief.yml`에 19:52 ~ 23:22 UTC **9개 cron**(04:52 ~ 08:22 KST, :07·:22·:52 등 한산한 분) + `workflow_dispatch(date)`. 정각·30분 예약은 혼잡으로 1~2시간 지연되거나 누락되는 것이 실측(2026-09-10: 05:00~06:30 예약 전부 미실행, 첫 실행 07:14)되어 v2.0.7에서 분 단위를 옮겼다.
- **잡 동작(idempotent)**: ① `archive/<오늘>/brief.json`이 이미 있으면 즉시 종료 ② 없으면 5분 간격으로 최대 45분 게시 감지(공개 미리보기 → 세션 폴백) ③ 감지되면 마지막 메시지 후 5분 대기(분할 게시 완료) → 생성 · 아카이브 커밋 · 배포 ④ 06:30을 지나도 미게시면 "대기 중" 상태 페이지를 1회 게시하고 계속 감지 ⑤ 09:00 이후 미게시면 "브리핑 없음"으로 status 기록 후 종료.
- **중복 방지**: `concurrency: {group: daily-brief, cancel-in-progress: false}` — 뒤따르는 예약 잡은 대기 후 ①에서 즉시 종료한다.
- **비용**: 잡당 최대 45분, 통상 2~5분. 공개 리포지토리는 Actions 사용량 무료.
- **대기 페이지**: 06:30 이후 미게시일 때만 게시. 헤더 · 최근 브리핑 링크 · "게시되면 자동 갱신" 안내(5분 간격 meta refresh) 포함.
